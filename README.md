Windows 优先、可跨平台的桌面效率工具：**截图 · 标注 · 贴图 · 取色 · 录屏 · 文字识别**。
C++23 + Qt 6 Widgets 实现，界面、图标与代码全部为本项目原创，不含任何现有产品的素材或商标。

- 常驻托盘，八个全局热键覆盖日常动作，不需要先开主窗口
- 一个可执行体加随包摆好的 Qt 运行时，绿色目录即可运行；同时产出 zip 与 NSIS 安装器
- 浅色、深色、高对比度三套主题，另有跟随系统；高 DPI 与多屏；中英双语界面
- 录屏编码走 `ffmpeg` 子进程，**随包分发、不链接**：装完即用，也不让 GPL 传染本体
- 每个模块都有单测，另有一条跨模块流程用例；四条验证线（本机两档 + 容器两档）都是必建必测的门禁

## 功能

**截图**
全屏 / 区域框选 / 当前窗口 / 多显示器 / 高 DPI。按下热键后整屏冻帧，直接在上面拖框；
遮罩同时认出光标压在的是哪一扇窗口并亮出它实际可见的那圈边界（比窗口矩形准，不含看不见的可调边框），
悬停还会细分到界面元素一级（Windows 走 UI Automation：先认光标下那扇窗，再按包含关系钻到按钮、输入框这些块上，
`,` / `.` 在层级间往上 / 往下走），原地按一下就选此刻亮着的那一块——整扇窗口或最深那一级元素，拖过之后要改就接着拖；
Enter 或双击确认，Esc 取消，选完立刻进标注窗。
框好之后还想改不必重框：选区落定后四角与四边中点各出现一枚抓点，按住它就是改这一块（鼠标形状会跟着变，
内部按住是整块平移）；方向键整块平移一格，按住 `Shift` 挪右下角一格。拖过头不会把选区翻面，贴到屏边就停下。
拖框途中选区里会浮出三分网格（两条竖两条横的构图参考线，与十字虚线同档：松手就收）。
要**精确**的尺寸或比例也有两条键盘路：裸按 `S` 开一个尺寸输入框，敲「宽x高」回车，选区左上角不动、按这个尺寸铺开；
裸按 `A` 锁上当前选区的长宽比（先框一个相近的再按），之后拖出的框都按这一档来，锁着的档跨轮次记住——想解开再按一次 `A`。
锁着时读数后面会标出「(锁定 16:9)」，不然拖不出想要的形状会被当成手抖；已经框好的块仍可自由拉抓点微调。
光标一进遮罩旁边就跟着一枚 9×9 像素放大镜，下面一行报这一点的全局坐标与颜色（默认 HEX，裸按 `C` 在 HEX / RGB /
HSL / HSV / HSI / 十进制六种写法之间轮换），卡像素边界时不必先截下来再放大看；贴到屏角时它自己翻到光标另一侧，不会跑出这块屏。
它不只出现在拖框途中：悬停挑窗口、拉手柄对齐边线、平移选区时同样跟着——最需要像素级读数的正是「按下之前」那一下。
平台列不出窗口时（如 Linux）退回纯手动框选，不假装这一格有；认不出界面元素时悬停只认整扇窗口，
元素那一级的读数与层级键一并缺席。
截完之后做什么由设置里那一档决定：默认进标注窗，也可以选复制到剪贴板、直接存成文件、
直接贴到屏幕上或直接识别文字——这四档都不弹窗，按下去就落到成品上，
成不成都有句提示（剪贴板与贴图这两步本来没有任何界面变化，不说就分不清「按了没反应」与「已经进去了」）。
另一格「延时截图」等 0 到 60 秒再开始，用来截菜单、悬停提示这类一碰就没的画面；等的时候会说一声，
延时期内再按一次只回一句「上一次还在等」，不叠第二层遮罩。
存成文件时写哪一种格式也可选：PNG（无损，默认档）、JPG、WebP，另有一格质量管着后两种
（「直接存成文件」与贴图右键的「保存」都吃这一档；退出前存的那份恢复数据永远是 PNG，
拿有损档存恢复数据会让桌面每次重启都糊一点，而没人要求过这种事）。图像编码器是插件，
这台机器写不出来的那一档不会摆进设置页——容器那份 Qt 就没有 WebP 的写插件，摆出来只会
让人选一次、失败一次。
「鼠标指针」那一格（默认不含）把指针画进成品：形状取的是系统此刻正在画的那一枚，配色与 DPI 都跟着系统走，
按指针的热点落位，尖端指哪儿就在哪儿。区域截图是先画进整帧再裁选区，选区里带不带指针就看它落没落在里面。
滚动长截图那一趟刻意不带——按帧接图会把一枚指针复制成一串。非 Windows 平台取不到系统指针的形状，
开着也画不出来，只在日志里说明这次不含指针。
遮罩里裸按 `P` 可以只翻这一轮：截菜单与悬停提示时想把箭头带上，下一张又想要干净的，为这个去设置里改两趟
不是出路；翻过之后读数后面标出「（含指针）/（不含指针）」，看不见的模式等于没给过这一档。这一档不写回配置，
也只活到这一次交付——托盘、热键、命令行那几路没有遮罩参与，照旧读设置里那一格。滚动长截图那一轮压根不提供
这一档（`P` 在那儿交回系统）。
截图完成还有几处动手就生效的开关（都在截图页）：开「自动保存」之后每张截图立即按上面的格式与目录存一份，
不弹提示（「截完之后」已经选了存文件或快速保存时不重复存）；开「截图音效」响一声系统提示音；
「截图后运行命令」填一条命令行（形如 `上传工具 --path "%file%"`），每一次截图交付完之后起跑它一次，`%file%` 换成这一轮落盘的成品路径；
这一轮没落成文件时（「截完之后」选的是进标注窗那一档）带 `%file%` 的命令会被拒并说出原因，不会把一条不存在的路径喂给外部程序，留空就是不跑；
全局热键「快速保存」（默认 `Ctrl+Alt+S`）不管「截完之后」设的是哪一档，按下就截、截完直接存文件并同时交剪贴板；
标注窗里 `Ctrl+P` 打印，成品按纸面等比居中画上去（打印不关窗——取消对话框或在打印之后接着改，现场都留着）。
「成品加边框」与「成品加投影」两格决定成品离开程序时（存文件、交剪贴板、打印）要不要围一圈框、
带一圈轻投影；贴到屏幕上那一张不加——那是显示，不是输出；存 JPG 时投影底下垫白（JPG 带不了透明通道）。
宽与色也能调：紧挨着多了「边框宽度」（1 到 12 物理像素，默认 2）、「边框颜色」（一段 #RRGGBB，留空回到默认的中灰）
与「投影宽度」（4 到 48 物理像素，默认 16）三格。三格各读各的、各回各的档——哪一格填歪了只把那一格打回默认，
另外两格照收；画布尺寸与绘制拿的是同一份参数，不会出现「框按新值、尺寸按旧值」那种错位。
截图页的「圆角截图」开上之后，区域截图的成品四角切圆（角上是透明像素），紧挨着的「圆角半径」那一格调切多圆
（1 到 60 逻辑像素，默认 12；比短边一半还大的半径自动收一半，不会把内容切光）——整屏、窗口与
滚动长截图不带：那几路的形状改起来各有各的意外。
复制出去的那张在 Windows 上同时挂着 CF_DIB、CF_DIBV5 与 CF_BITMAP 三路（本机探针实测），只认 DIB 的旧程序也吃得到。
标注窗里按 `F5` **就地刷新这一块**：对着同一块屏幕区域重抓一帧换上，画好的标注、选中与撤销历史全部原地留着；
按住不放由键盘自动重复兜住——每一次重复按键就是一次重抓，刷到画面追上为止。刷新走的不是「新截图」那条路：
不响音效、不触发自动保存、也不往最近选区里再记一笔。
滚动长截图（`Ctrl+Alt+L`、托盘菜单与主窗口动作条上都有这一条）：先框出一条要滚的区域，之后按固定节拍反复抓这一块，
每帧自己认出与已接部分的重叠、只把新的一段接下去；过程中浮一条控制条报「已接多少像素」，
按完成就当成一次普通截图交出去（去向仍由设置里那一档决定），按取消整段扔掉。
接的过程中再按一次截图会被当场拒掉并说明「先按完成或取消」——铺第二层遮罩会让手里那张接了一半的图
既没交也没作废。
页面每几行重复一次时接缝会同时对上几个长度，取的是最长的那一个——收短的会把同一段接两遍；
只对上几行（两页开头都是空白）就当没接上，中途换屏或改缩放让宽度对不上时当场报错，
而不是悄悄接出一张歪图。

**标注**
工具十三件：矩形、椭圆、箭头、直线、画笔、高亮、马赛克、高斯模糊、文字、序号、橡皮擦、折线、放大镜。马赛克是「读不出」，
高斯模糊是「还看得见轮廓、认不出字」——对着截图写说明时后者更常用，两者都取底图自己的像素而不是叠一层色。
折线是「点一下落一个折点、双击收笔」的走法（松手不等于落定，最后那段在收笔时并入）；
放大镜拖出一个源框，框里那块底图按 2 倍放大画成旁边的插图（右侧放不下自动翻到左侧），源框自己围一圈虚线标出「放大的是这里」——
它是一面镜子：只照底图自己的像素，别的标注不进插图，镜子照的那块也一个像素都不改；
橡皮擦沿笔迹擦回底图：扫过的地方露出原图那一块，擦掉的是这一刻已经画上去的东西——层叠按画的先后走，
后画的图形照样能压在擦痕上；线宽滑块就是它的粗细；一笔擦除是一步独立的撤销，擦过头按 `Ctrl+Z` 就收回来。
色板、线宽、字号、「填充」（无 / 半透明 / 实心，矩形与椭圆用）、「圆角」（四角按短边比例切圆，矩形用）、「线型」（实线 / 虚线 / 点线，
矩形、椭圆、直线、箭头、画笔、折线六件描边类工具用）、「双向箭头」（箭头两端各一个箭头）、
「箭头样式」（实心三角 / 空心三角 / 开口两翼：末一档是只有两笔的「→」，杆一直伸到尖上）、
「箭头大小」（小 / 中 / 大：头长相对线宽 2.5 / 3.5 / 5 倍）、
「马赛克粒度」（细 / 中 / 粗）、「高亮透明度」（轻 / 中 / 重）与「高亮加宽」（窄 / 中 / 宽：高亮相对线宽 2 / 4 / 8 倍）各自可选，
「椭圆形状」是马赛克、高斯模糊、高亮、橡皮擦四件共用的形状开关：开着时马赛克与高斯模糊的作用区收进拖框的内切椭圆、
高亮与橡皮擦的两头换圆头圆角，关着则是矩形区与方头那一档（橡皮的方头与圆头同样往外伸半个笔宽，只换角的形状）；
序号有「计数组」三档（第 1..3 组循环）：每一组各自从 1 连排自己的号、点名（`+`/`-`）与「归零」也各记各的，
切组之后再落牌从那一组的下一号接着走；
**色板按形状各记一格**：给箭头挑了红、再切到序号挑蓝，切回箭头时还是红——同一张画布上「箭头一律红、序号一律蓝」
是写说明时最常见的配色，切一样东西就得重新挑一次色太磨人。没为某个形状挑过色时沿用当前这一格（切个工具颜色就跳，
比多记一格更让人以为程序出错），按下的那格色块也跟着形状走，界面说的就是画出去的那一支色。
**在色板那一排上滚滚轮调不透明度**：滚一档 5%，最淡 10%、最实 100% 两头夹住（滚到底也不把 alpha 归零，
那一笔会彻底看不见）；滚在工具按钮或滑块上不改颜色，淡掉的这一支同样记在当前形状那一格上，
现在的百分比写在「自定义颜色」那枚按钮的提示里。
文字还有字体族下拉、粗体 / 斜体与描边 / 背景四个开关，描边开着时「描边色」按钮在 自动（与字色反差）/ 白 / 黑 三档里循环，
「描边粗细」在 细 / 中 / 粗 三档里循环（起点那档就是早先写死的厚度，老图样重画不出第二个粗细）；
背景开着时「底板色」按钮在 自动（与字色反差）/ 白 / 黑 / 用标注色 四档里循环——最后一档把这一形状那支色垫在底下，
字身同时自动换成反差色，否则字压在同色板上等于不存在。落笔后的内容是**多行**的——
行内输入框里回车换行（框随行数长高），`Ctrl+回车` 才会落定；
撤销重做、复制、保存、贴到屏幕上、送去识别、识别二维码都在同一排按钮上，选中的标注可以拖动与删除；
拖完还想挪一像素用方向键（按住 `Shift` 走十像素），不必重画。
选中框上带八个缩放手柄与一枚旋转柄：拖角或边改大小（转过的图形沿它自己的两条边伸缩，拖时按住 `Ctrl` 以中心为不动点、按住 `Shift` 保持长宽比），拖框外的圆点绕中心转角度；
按住 `Ctrl`（反选）或 `Shift`（加选）点几条可以多选，多选整组挪、整组删、整组改样式，各是一步撤销；
`Ctrl+C` / `Ctrl+V` 复制、粘贴副本（副本带一点偏移，连续粘贴一次比一次再挪一格，一次粘贴是一步撤销）；
层叠按画的先后走，后画的压在先画的上面，`Ctrl+Shift+↑` / `Ctrl+Shift+↓` 挪一层、`Ctrl+Shift+Home` / `Ctrl+Shift+End` 直接到底 / 到顶。
打错了字也不必删了重打：双击那条文字，原地弹出带着原文的输入框（光标落在文末），
改完 `Ctrl+回车` 落定——这是一步独立操作，`Ctrl+Z` 回到改之前那一份文字，而不是把整条抹掉；
输入框里按 `Esc` 是取消（重编的那一格不动原文），点到画布别处按「就这些字」落定。
标注不必先从屏上截一块：托盘与主窗口里的「新建空白画布标注」摆一张 1280×720 的白底画布进同一套画布，
写字、画框、把几张截图拼起来说明时不用随便截一块屏当底。它不走截图那条链——没有帧、不记「上次选区」、
不触发音效与自动保存、也不进历史；正因为来源区域是空的，`F5` 刷新在这一轮会自己拒并说明原因（没得可重抓）。

**贴图**
把图钉在屏幕最上层对着用。滚轮缩放（一格 1.1 倍）、`Ctrl`+滚轮旋转、`Shift`+滚轮调透明度，
左键拖动移动，`R` 转正一挡（`Shift+R` 反向，一挡 90°）、`0` 或左键双击回到原始比例与角度（透明度不动，
那是用户刻意调的一档）、`T` 缩到一枚小方块再按还原（缩放与旋转原样留着，只是先让开地方；
那枚方块默认 48 像素，**拖它的四边与四角就给它定大小**，24 到 240 之间随你，中间那一按一拖还是挪它——
方块定多大与那张图缩放到几倍是两件事，退出方块后回到的是你自己调好的那份倍率，这一档也跟着这张贴图留着），
`H`/`V` 左右与上下翻转、`G` 灰度显示、`I` 反色——四个视图变换都只改「看」：复制、保存、标注、识别
拿到的仍是原始像素（与旋转同一条规矩），右键菜单里各有一项、勾选态与键位同解；
方向键把这一张逐像素挪走（裸按一格、`Shift` 十格，与截图遮罩和标注窗同一张键位表；多选时整组按同一位移跟上），
`Ctrl+V` 用剪贴板里那一份换掉这一张——图像、文本卡片与颜色卡片都能换，摆的中心与缩放倍率原地不动，
而换上去的像素就是之后复制、保存、标注、识别拿到的那一份（与视图变换相反，这一条是真的换了内容）；
动图这一档当场拒并说明出路：下一帧会把换来的那份盖掉，先存成静态图再贴一张来换。
`Ctrl`+左键点几张可以**多选**（选中的那一圈加粗描边）：拖着其中任意一张，整组按同一位移一起挪；
Ctrl+滚轮转、Shift+滚轮调透明度仍只动这一张，而普通滚轮缩放整组按同一倍率跟着缩；
右键菜单里那句「已选中 N 张」下面是整组入口——关闭 / 保持置顶 / 鼠标穿透 / 缩到小图 / 四个视图变换都对整组生效，
另有一项「批量保存（N 张）」把这几张逐张按设置里的目录与命名模板写成文件（同一次里撞名的自动让位；
成几张、几张没写成与第一条原因都在提示里说清，一张都没写成时那句就是能做的事——换个目录）；
内容相关的标注、裁剪、取色、识别与单张「保存」仍只动这一张，末尾一项「取消选择」；
`Esc` 在多选里先清选择、再按一次才关这张；切组与「全部收起」都会清掉选择；
右键菜单「背景色」给这张垫一层底色（跟随主题 / 白 / 黑 / 灰 / 自定义…）：透明像素处露出来的就是它，
与别的视图变换一样只改「看」、不进成品；不垫时露的是主题的窗口底色（这张窗口本就不是透明背景）；
右键菜单「透明区」管带透明通道的那张图，透明像素底下画什么，四档：跟随窗口底色（一直以来的那一档）、
桌面透出（整窗改逐像素合成，那几块把底下的桌面让出来）、深色棋盘 / 亮色棋盘（按 8 像素一格垫一片棋盘，
看清透明的边界在哪；深浅两档是因为底上可能是白文档也可能是深色桌面）。棋盘同样只改「看」、不进成品，
这一档跟着这张贴图存进布局，重启回来还是它；整张图不透明时这四档看不出差别。
右键菜单「只显示这一张」把屏幕腾给它（其余的先收起来），再点一下原样摆回——
新贴一张、切组、整桌收起或主角自己被关掉时这一档自动落掉；
右键菜单「裁剪」进裁剪态：拖一个框（框外压暗）、回车或双击裁到那一块，`Esc` 原样退出——
进裁剪与进标注一样先把旋转与翻转摆正、退出时恢复；动图的「裁剪」与「标注」一道灰掉并写明出路
（裁完会被下一帧盖回原尺寸，先另存成静态图再贴一张来裁）；
右键菜单复制 / 复制为文件 / 自定义尺寸… / 保存 / 识别文字 / 标注 / 取色 / 裁剪 / 缩到小图 / 保持置顶 / 鼠标穿透 / 窗口阴影 / 平滑缩放 / 关闭 / 销毁这一张，`Esc` 关闭本张；
拖四边与四角也能改大小：光标挨着那一条边就换成对应的双头箭头，按住拖就是把这一张等比放大缩小
（与滚轮、右键「自定义尺寸…」同一档倍率，只等比不拉伸；抓哪条边就以对面那条为锚，拖右边时长出去的是左边在退）；
贴图中间那一片仍是整张平移的落点。
关掉这一张分两档，差别只在**还按不按得回来**：「关闭」与 `Esc` 是同一条，摘掉之前把像素抄进「最近关掉的贴图」那份册子
（最多五张，最新在前），托盘上「重新贴出最近关掉的贴图」按一次报销一张——贴回光标处，连来源文件一起带回来（动图接着播），
提示会说还剩几张可报，册子空了也说一句而不是静默；「销毁这一张」摘得干净，不抄那一份像素，托盘那条再也碰不到它。
整桌收起与切组都不算关掉（图还在册）；「关闭」在整组入口里对全组生效并逐张抄进册子，「销毁」刻意不放进整组——
一次毁掉一桌太顺手了，手滑的代价在这里是拿不回来的像素。
「复制」交的是像素（粘进文档是一张图），「复制为文件」交的是一条本地路径（粘进资源管理器/聊天窗口落一份 .png，
落在缓存目录里、按内容起名，同一张图重复复制复用同一个文件）。
「自定义尺寸…」把滚轮的一格一格换成精确值：敲「宽x高」（与截图选区那个输入框同一套写法），
按宽缩放、高跟比例走——想两维都吻合就先裁成那个比例；超界的值夹在缩放区间里。
「窗口阴影」给这一张围一圈投影（几圈递减的暗晕）：窗口比内容每边大一圈，内容坐标、选中框、
取色与吸附位置全都不动——内容在窗口里居中，留边出现或消失对它零影响；缩到小方块（T）时不带。
右键菜单里的「平滑缩放」管放大时怎么铺像素：开着按插值铺平，关掉则一格源像素就是屏上一块硬边方格——
放大到两三倍读截图里的小字时，插值会把笔画糊成一片灰，关掉才认得出那一格是什么。它与四个视图变换一样
只改「看」：复制、保存、标注、识别拿到的仍是原始像素，默认开着（与 Qt 的绘图缺省档一致）。
键盘与双击走的是同一个复位出口，两条路不会将来只改一处。
右键菜单里的「标注」就是**在贴图上直接标注**：整窗变成一张标注画布（工具、快捷键、撤销与标注窗完全同一套），
`Esc` 收工把画上的东西烘进这张图——贴图不关，这是「给它添一笔」而不是「丢弃」；
工具栏上复制 / 保存 / 贴到屏幕上 / 识别文字四个按钮（以及回车、`Ctrl+S`、`Ctrl+D`、`Ctrl+O`；打印只在 `Ctrl+P` 上）
都是「收工并做这件事」；「贴到屏幕上」是把成品**另贴一张**新图（留底再贴一份），不动原张。
旁边还有「识别二维码」：认出画面里的二维码/条形码就把文本复制进剪贴板，认没认出来都**不关窗**——
多半只是想知道「这里头是什么」，顺手关掉现场是最烦的一种收场（与打印同一条口径）；
一张图里有多个码时优先挑二维码（一维扫描在二维码的花纹里偶发假阳性），提示里报出认出几个。
后端是 zxing-cpp（Apache-2.0，许可证正文随包发；没编进来时按钮报明原因）。
旋转过的贴图进入时先转正、收工转回原角度（批注跟着图一起转）；贴边收着的不在标注中收回；
动图的「标注」是灰的——标注会被下一帧盖掉，先另存成静态图再贴一张来标。
盘上的文件与链接可以直接**拖到贴图上**贴成新图：图片文件按盘上的像素读出来（GIF 这类动图贴上去接着播），
网页链接渲染成文本卡片，纯文本与颜色写法和剪贴板那条路一样各有卡片；拖进来几张就贴几张，
后一张向右下错开一格；不是图片的文件不拦整次拖放，能贴的照贴，贴完那句提示会点名哪些没贴。
退出前把还在桌上的贴图连像素一起记下，下次启动摆回原位——置顶、鼠标穿透与「收起全部」那一档
也一起记：不置顶的那张回来还是不置顶，穿透过的还是穿透，「收起 / 摆回全部贴图」那一档状态照旧
（托盘上那句就是出口）；某张图被清掉时只跳过那一张。
开着鼠标穿透的贴图收不到右键，也就关不掉自己那一档——托盘上「取消全部贴图穿透」就是这条死路的出口（没有这能力的平台上这一条根本不放），
按下去说清恢复了几张，一张都没开时也说「没有贴图开着鼠标穿透」，不让人以为程序卡住了。
要临时把桌面清干净不必关掉贴图：托盘与 `Ctrl+Alt+H` 那一条把整桌一起收起来，再按一次原样摆回——
收着的图还在册（张数、摆位、缩放、透明度都不动），只是不在屏上；因为收着的时候点不到它，摆回这一格也只放在托盘与热键上。
托盘上还有一条「把剪贴板里的内容贴到屏幕上」，按一下就在光标处落一张贴图：剪贴板里是**图像**就原样贴；
是**一段纯文本**就渲染成白底深字的卡片（宽度封顶后折行，一个断不开的长词按字符断，最多 2000 字）；
是**颜色写法**（`#`、`rgb(`、`hsl(` 开头的短单行）就渲染成色块加写法条的颜色卡片——把「red」这类普通单词
当成颜色、或者把一段英文渲染成色卡，都是不做的，只认那三种写法。剪贴板里是**文件**（资源管理器里复制的那一份）
就走拖放那条转换：图片贴出来（多件依次错开、动图连来源带走继续播），一件都不是图片时给一句说明而不是静默。
贴图可以分组摆放：每张贴图在右键菜单里「移动到分组」——列出现有分组和一项「新建分组」，
移出当前组的那张先收起来（换组放着＝腾地方）；桌上只放当前组，`Ctrl+Alt+G` 或托盘里那条
「切到下一组贴图」在现有分组之间轮换，切到哪一组会有提示。分组号与当前组都跟着贴图布局记下，
重启后回到同一组；某一组的贴图全被关掉时这一组就没了，当前组自动回落到第一组。
轮换的顺序还能自己排：通用页那一格「分组轮换顺序」填逗号分隔的组号（如 `3, 1, 2`），切组就照这一圈走；
没写到的组补在末尾、不在册的组号跳过，所以新建的一组立刻切得到，不必先回设置里补一笔；留空即按组号升序，
填歪（非正整数或同一个组写两次）的那一次不写进配置，提示会点名是哪一格——同一组在一圈里出现两次，切组就会多跳一步。
分组还能起名字：同一个子菜单里「重命名这一组…」敲一个字（留空就是取消命名，回到「分组 N」这种叫法），
起过名字的组在菜单与切组提示里都念名字（`分组 2：参照对比`），号还是那个号——名字只是挂在后面的标签，
不替掉它，布局与切组都按号走。同处还有「删除这一组」：把这一组的贴图并回第一组（不是扔掉），名字跟着清掉；
第一组是并回来的落点，那一项在它上面是灰的并写明原因。名字跟着组一起过夜也一起消失：组空了名字就没了，
不会留下挂在看不见的组上的标签。
全桌的分组还有一扇专门的窗：托盘与主窗口动作条里的「贴图组管理…」（开着就不开第二扇，只抬那一扇并重读一遍），
三列一张表——哪几组在册、各有几张、哪一组此刻摆在桌上。张数算的是**在册**的而不是看得见的：收着的与在别组的那几张
都属于这一组，按看得见的算就会少报，看着像那张图没了。选中一行才能按下四个动作（没选中时按下去也不知道该管哪一组）：
「摆出这一组」把活动组换成点名那一组（没人的一组的拒绝会说清怎么把图挪过来，切过去等于把整桌收空，那种事不做）；
「重命名…」与右键那一条同一个出口；「腾空这一组」关掉这一组在册的全部贴图，走的是**关闭**那一档而不是销毁——
提示里跟着说清「还能按回最近 5 张，更早的找不回来」；「删掉这一组」把成员并回第一组、名字跟着清，
删不掉第一组那句拒绝住在管理器里，界面上不另写一套「哪些组能删」。
表上不摆空壳组：本仓的一组由「有贴图在册」成立，所以这里没有「新建一个空组」那一条——
新建一组的路径是右键「移动到分组 → 新建分组」，一句出路写在空表的提示上。
右键菜单里还有一条「取色」：进去之后鼠标变成取色笔，悬停出读数（写法跟着设置里那一档走），
点一下就把那一像素的颜色复制进剪贴板，取完自己退出；这一档里 `Esc` 只退出取色，不关贴图。
「保存」按设置里的目录与命名模板写一份，「在文件夹中查看」先写一份再打开那个目录——
贴图的像素在内存里，没有别的「它所在的文件夹」。
贴图拖到屏边附近松手会贴上去（吸附容差 12 像素，越界的先夹回屏内——夹回来之前能把一张图整个
拖出屏幕，从此再也点不到）；贴边之后指针一离开就收成 6 像素的一条，悬停再展开，右键菜单里
「贴边隐藏」也能直接收发这一档，拖离屏边自动脱开。
按住 `Shift` 拖动时，这张图会吸向**桌上其他贴图与屏上别的程序窗口**的边线：六条线一起比（左 / 中 / 右、
上 / 中 / 下），每一轴取位移最小的那一条，容差沿用那 12 像素——只比外边线的话，一窄一宽两张永远对不齐中心。
参照在起笔那一刻取一次快照、整趟拖动都用它，不然每帧重新枚举一遍窗口就把鼠标移动拖慢了；不按 `Shift` 一律不吸，
自由摆放的手感不被参照抢走。`Ctrl+A` 把桌上看得见的贴图一起选进多选集（收着的与在别组的那几张不算——
整组动作落到看不见的图上，比没生效更难解释）。
动图（GIF/APNG）贴上去会接着播：只认「文件」这一条来路（历史那页贴出来的、以及上次会话留下的
动图），来源路径跟着布局记下，重启后接上继续播；剪贴板与标注贴出来的图在内存里，没有帧序列可播。
藏起来或收起的动图会停下，不在屏上就不烧 CPU。

**屏幕取色**
全屏冻帧 + 9×9 放大镜，点一下按选定格式（HEX / RGB / HSL / HSV / HSI / 十进制）把颜色复制走。
遮罩底边还摆着一行「最近取色」的色块（最多 8 条，最新的在前）：点色块或按数字键 1–8 就把那一档取回，
不用回到原处重新对像素。贴着屏幕取色与贴图右键的取色共用这一份记录——从哪儿取的色都在这一行上。

**录屏**
范围可选整屏 / 上次选区 / 当前窗口，输出可选 MP4 / GIF，帧率、画面码率、光标高亮、倒计时秒数（0–10，0 表示立即开始）、
视频编码器（自动按偏好顺序逐个真探，也可以钉住某一家；GIF 档下帧率那一格自动收在上限 24，切回 MP4 恢复你原来那一档）、
麦克风与系统声音各自可开（两路都开时混音）。控制条显示状态、时长与 3-2-1 倒计时，
可暂停、可取消（这一段整段扔掉：不封盘、不起编码、临时帧当场删掉），可贴边、可最小化到托盘——
收起后托盘那一行仍报「正在录制 / 已暂停 + 时长」。停止之后再按取消会被拒，理由说在提示里
（那一份帧正是后台编码在读的输入）。
停止后编码在后台线程进行，界面不冻；编码器在编码前用真 `ffmpeg` 探一遍，取第一个开得起来的。
抓帧在 Windows 上走 DXGI 桌面重复（抓一帧中位 6.0ms），开不了这套原语的机器回落 Qt 的 `grabWindow`
并在日志里点名用的是哪一套。

**文字识别**
`Windows.Media.Ocr`（用系统自己装的语言包，无需放文件）与 Tesseract 两个后端，按平台与可用性自动选型。
结果窗口左侧原图、右侧文本，点一行就在图上圈出那一行；可导出 TXT / JSON，可换语言重认。
托盘还有一条「识别图片文件…」，挑盘上的一张图直接认。

**命令行**
不带参数启动即常驻；带参数就是「跑一件事」的启动，不锁单实例、不登记全局热键——托盘里常驻着一份时照样能用。
`--capture=full|region|window` 截一张，默认存成文件并复制进剪贴板，把文件路径打到标准输出、退出码给成败
（`region` 用记下的「上次选区」，没有记过时当场报错）；`--pin <文件>` 把盘上的图片贴到屏幕上（保持运行）；
`--pick` 进入屏幕取色（保持运行）。
交付去处可以点名：`--to=file,clipboard,pin` 一次落几处，逗号分隔，交付顺序恒为「存文件 → 剪贴板 → 贴到屏幕上」，
认得的只有 `file` / `clipboard` / `pin` 这三个词（区分大小写，写歪、写重、多写一个逗号都当场拒绝并列出可取值）；
点了 `pin` 就不再退出——那张贴图属于这个进程，退出会把它一起带走，与 `--pin` 同一档做法。
截完还能接着跑一条外部命令：`--exec="上传工具 --path %file%"`，参数里的 `%file%` 换成这一轮落盘的成品路径；
这一轮没落成文件时带 `%file%` 的命令会被拒并说明原因（不给它喂一个不存在的路径）。
设置的截图页有同一件事的日常档：「截图后运行命令」，每一次截图交付完之后跑，命令行给了 `--exec` 时以那一条为准。
`-h` / `--help` 打用法说明，`-v` / `--version` 打版本号，
`--selftest` 仍是「启动路径自检」；参数写错、一次给了两个动作、或把 `--to` / `--exec` 配到 `--pin` `--pick` 这类
没有「截完之后」这一步的动作上，都会当场拒绝并附上用法说明（退出码 2）。

**历史记录**
写出过文件的成品进列表（缩略图 + 时间 + 类别 + 尺寸）：「直接存成文件」、标注窗的「保存」与录屏编出的成品都算，
只复制到剪贴板或只贴到屏幕上的那一次没有文件，默认也就不进列表。通用页的「未保存的截图也进历史」拨开之后，
那一张会在程序数据目录下的 `Unsaved` 里留一份无损像素（永远写 PNG，透明通道不丢；最多 50 张，超出按写入时刻裁掉最旧的，
目录里别人放的文件不动），于是误触 `Esc` 丢掉的那一张也还在列表里——写不进去会当场说一句，不会静默假装留过了；
这一档默认关，开着它每截一张就往盘上多一份。录屏那一类不解视频帧，缩略图取不出画面时摆一枚类别图标。
尺寸读不出时列表文案不带那一格，而不是打一个「0×0」冒充读数。可按文件名、类别或日期搜索，可按类别筛选，
次序固定时间倒序。每条可以贴回屏幕上、送去识别、打开它所在的那个目录，或单独移除；「清空列表」一次去掉全部记录，
会先问一句，且动的只是清单——成品文件留在各自目录里，软件不替用户做不可逆的那一步。按条数与天数保留（填 0 即不限）。

**其他**
中英文界面（英文档随包带语言包）、浅色/深色/高对比度三套主题与跟随系统、单实例检测、未捕获异常兜底
（写一条中文日志再以退出码 70 退出）、托盘作为找不到窗口时的入口。
关于页有一条「检查更新」：按一下才联网去本仓的 GitHub Releases 问最新正式版，有新版就把版本号与下载页
摆出来（点那行文字用系统浏览器打开）。**这是程序唯一的联网点**，不是启动就查；只做「查」不做「换」，
理由见路线图。

## 快速开始

已经构建好（或拿到打包产物）时：

```powershell
# 绿色目录或安装后的可执行体
GyanisScribe.exe            # 起托盘，按 Ctrl+Alt+A 截第一张图
GyanisScribe.exe --help     # 启动参数
GyanisScribe.exe --selftest # 把启动路径跑完就退：日志接管成功即退出码 0；热键登记的结果只打进日志，撞了不把这一格判红
```

第一次运行要知道的三件事：

1. 程序常驻托盘，关掉主窗口不会退出进程，退出只走托盘菜单那一条路。托盘装不上的环境没有这条路
   （无托盘的桌面、容器里）：主窗口会在启动时自己现身，关掉它就是退出程序。
2. 全局热键默认 `Ctrl+Alt+A`（截图）、`Ctrl+Alt+R`（录屏，再按一次停止并保存）、`Ctrl+Alt+O`（识别）、
   `Ctrl+Alt+P`（取色），撞了就撞了——设置里可改，改完立刻重新登记，不用重启。
   哪一条没能登记上，启动时会在气泡里连它各自的原因一起说出来，不留「按了没反应」让人猜。
3. 录屏用的 `ffmpeg` 与识别语言包都在安装包里，程序目录里就能看见；不需要再装任何东西，
   也不需要往哪个目录放 `traineddata`。

Linux 侧当前是「可构建、可运行、能力降级」：抓帧、标注、贴图、识别可用，
全局热键与录屏取声没有平台后端——热键页那八行会按能力位灰掉并在页首写明改了也不会生效，
取声那两格给出中文降级原因，都不会静默失败；托盘同样没有，所以主窗口在启动时就现身。

（「缩到小图」那一项与 `T` 同一条路，四档视图变换各有一项）。
四边与四角也能拖：光标挨着边就换成那一条边的双头箭头，按住拖就是等比改大小（对面那条边钉住，与滚轮同一档倍率）；
缩成小方块的那一档，拖它的边就是在给那枚方块定大小（24 到 240 像素之间，中间那一按一拖仍是挪它）。
`方向键` 把这一张逐像素挪走（一格）、`Shift`+`方向键` 走十格——与遮罩、标注窗同一张键位表，多选时整组一起跟上；
`Ctrl+V` 用剪贴板里那一份换掉这一张（图像 / 文本卡片 / 颜色卡片都能换，摆位与倍率不动；动图会当场说明为什么不换）。
`Ctrl+A` 把桌上看得见的贴图一起选进多选集；拖动时按住 `Shift` 就是把这一张对到别的贴图或屏上窗口的边线上（松手即落定）。
没绑定的字母一律交回 Qt，贴图窗不抢输入法与系统快捷键。

## 设置与配置文件

设置窗口左侧按类别竖排：通用 / 截图 / 标注 / 贴图 / 录屏 / 文字识别 / 快捷键 / 主题 / 关于 / 历史，
每页顶部一句说明写清这一类管什么。除界面语言（重启后生效）外，改完立即写入配置：
截图完成后做什么（进标注窗 / 复制到剪贴板 / 直接存成文件 / 直接贴到屏幕上 / 直接识别文字）、延时截图的秒数、截图后运行的外部命令、
截图含不含鼠标指针、成品存成 PNG / JPG / WebP 与有损档的质量、**成品文件名的模板**、标注默认线宽与字号、贴图默认不透明度、录屏范围与输出格式、默认帧率与光标高亮，
从下一次截图、新建标注窗、新贴一张图、下一次开始录屏时起用。
文件名模板的变量只有三个：`%date%`（yyyyMMdd）、`%time%`（HHmmss）、`%ms%`（三位毫秒），其余原样写进名字；
截图、贴图右键的「保存」、识别结果导出与录屏成品共用这一格，留空即默认档（`GyanisScribe_%date%_%time%_%ms%`）。
填歪了（含路径分隔符、认不出的变量）不会写进配置，格子里的提示会说明原因；模板里去掉 `%ms%` 之后同一秒连拍会同名，
这时候后一张自己让位成 `…-2`，不覆盖前一张。
「通用」页还管着历史保留多少条、多少天（填 0 即不限）、**开机时自动启动**（写当前用户的启动项，不需要管理员；
状态读的就是系统里那一条，不在配置里另存一份，所以用户在系统「启动」设置里手动改过之后这里跟着变），
以及「导出配置… / 导入配置…」——
把全部设置写成一个 JSON 文件，换机器与备份时用；导入后订阅配置的热键与主题立刻跟上新值，
而当前那一页显示的还是导入前的值，关掉设置窗重开就对新。

| 用途 | 位置 |
| --- | --- |
| 配置 | Windows 注册表 `HKCU\Software\Gyanis\GyanisScribe`；Linux `~/.config/Gyanis/GyanisScribe.conf` |
| 配置（便携模式） | 程序目录旁放一个空的 `portable.txt`，配置就改读写同目录下的 `GyanisScribe.ini`——启动日志里会写明「便携模式」；**只有配置跟着走**，日志、历史、缓存与成品目录仍在下面各自的位置（要连数据一起带走得另立一套根路径设计，见路线图） |
| 截图默认目录 | 用户图片目录下的 `GyanisScribe/`（可在设置里改） |
| 录屏默认目录 | 用户视频目录下的 `GyanisScribe/`（可在设置里改） |
| 日志 | `<AppData>/Gyanis/GyanisScribe/logs`，每条都是中文，界面切成英文也不翻译日志 |
| 崩溃转储 | 同一个日志目录下的 `GyanisScribe_<版本>_<时刻>_<进程号>.dmp`；反馈时把日志与这份一起发回来才定位得动 |
| 贴图恢复数据 | 缓存目录里的像素文件，配置里只存路径与几何 |

界面文案是中文，走 `Core::uiText()` / `Core::uiTextUtf8()`；英文档需要
`translations/GyanisScribe_en.qm`（随包分发，缺包时按中文继续并给出放置位置）。
翻译目录 `Translations/GyanisScribe_en.ts` 是唯一真源，`.qm` 由构建期的 lrelease 产出。
改完文案要重新生成目录：


## 从源码构建

### 前置要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| 编译器 | MSVC（本机实测 14.51）/ GCC 13 | 需要 C++20/23 的 `std::expected` 与 `std::format` |
| CMake | ≥ 3.28 | — |
| Ninja | — | 生成器 |
| Conan | 2 | 依赖：spdlog 1.17.0、GoogleTest 1.17.0，Release 档另领 Tesseract 5.5.2 |
| Qt | 6.11，含 Core / Gui / Widgets / Concurrent / Svg / Network | Linux 容器里用发行版的 6.4 也可编 |
| Python | 3 | 两条静态门禁脚本 |
| ffmpeg | 官方静态构建（gyan.dev） | 打包时需要：`scripts/FetchFfmpeg.ps1` 按钉好的 URL + SHA-256 取进 `Vendor/Ffmpeg/`；开发期 PATH 上有一份也行 |
| NSIS | — | 可选：只在打安装器时需要 |

机器相关的路径只出现在 `scripts/WindowsBuild.bat` 与 `scripts/container/env.sh` 里，工程不写死绝对路径。

### Windows

```bat
set QTDIR=G:\Tools\Qt\6.11.1\msvc2022_64
scripts\WindowsBuild.bat release
build\release\bin\GyanisScribe.exe --selftest
```

`WindowsBuild.bat` 自己调 `vcvars64`、按预设配置、编译并跑 `ctest`，一条命令就是一条门禁。
预设两档：`debug` 与 `release`。Windows 上两档都带系统识别后端（`Windows.Media.Ocr`），
只有 `release` 额外领 Tesseract——上游 leptonica 的 Debug 包与其 `cpp_info` 对不上，
细节与撤除判据见 [docs/OcrBackends.md](docs/OcrBackends.md)。

`CMakePresets.json` 里的档位名不分平台：`debug` / `release` / `asan` / `tsan` / `coverage` 五档，
两侧共用同一份文件。用哪套工具链不由预设名决定，而由进入构建的那一步决定：
Windows 侧 `WindowsBuild.bat` 先调 `vcvars64`，容器侧 `env.sh` 设 `CC/CXX=gcc-13`，
Conan 再按各自平台的 profile（`Conan/Profiles/WindowsMsvc2022` 与 `LinuxGcc13`）指过去。

### Linux（容器内验证）

```bash
docker build -f Dockerfile.dev -t gyanisscribe-dev .
docker run --rm -it -v "$PWD:/work" gyanisscribe-dev bash
```

容器内五件一键脚本（`scripts/container/`）：

```bash
scripts/container/init.sh          # 补包并体检工具链（幂等，可 SKIP_APT=1 只体检）
scripts/container/build.sh debug   # 也支持 release / asan / tsan / coverage
scripts/container/test.sh debug    # 有 Xvfb 就在虚拟屏下跑，界面用例才算真被跑到
scripts/container/sanitize.sh      # ASan(+UBSan)；tsan 档另说，见下方边界
scripts/container/coverage.sh 55   # gcovr 汇总，阈值不过就红（判定由 --fail-under-line 做）
```

sanitizer 的运行期参数（含 LSan 那张只放过系统库字体缓存的抑制表）统一在 `env.sh` 里导出，
所以 `sanitize.sh` 与「`build.sh asan` + `test.sh asan`」两条入口给的是同一个结果。

要跑 TSan 这一档得放开 seccomp：这台内核（WSL2 6.18）下 libtsan 必须关 ASLR 才起得来进程，
而 `setarch -R` 走的 `personality` 被 Docker 默认 seccomp 档拒绝（实测 EPERM）。
脚本会在建之前先探这一点并当场报红，不会把「没跑」当成「跑过」：

```bash
docker run --rm -it --security-opt seccomp=unconfined -v "$PWD:/work" gyanisscribe-dev bash
```

## 打包

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\WindowsPackage.ps1
```

产出绿色目录 + zip + NSIS 安装器，落在 `dist/`。脚本用 `windeployqt` 按可执行体的**实际导入**摆好
Qt 运行时，然后在 staging 目录里把 `PATH` 收窄到只剩 `System32`、并清掉 `QTDIR` 与
`QT_PLUGIN_PATH` 那几条提示，再跑一次 `--selftest` 与 `ffmpeg.exe -version`。
为什么收窄：开发机的 `PATH` 上本来就有 Qt，缺了哪件 DLL 也会被本机那份悄悄补上，
「本机能跑」就不是「包装完能跑」的证据。这条判据本身也验过能不能红：在同一份 staging 里
把 `Qt6Widgets.dll` 挪开，`--selftest` 的退出码变成 `-1073741515`（`0xc0000135` = 找不到 DLL），
放回又回到 0。安装器带卸载段。

VC++ 运行库也随包带：可执行体导入 `MSVCP140.dll` 与 `VCRUNTIME140.dll`（还有 `_1`、`_2` 两份），
这几件不属于 Windows 自带的系统映像，新装机上要么先装 redist 要么程序起不来。打包脚本按编译器版本
从工具链的 `VC\Redist\MSVC\<版本>\onecore\x64\Microsoft.VC145.CRT` 取那五份摆到可执行体旁边
（Windows 先搜程序目录，加载的就是随包这一份），缺任一件当场中止；UCRT（`api-ms-win-crt-*`）不搬，
那是 10/11 自带的。`windeployqt --compiler-runtime` 在这套 Qt 上一个 CRT 都不落地（实测），所以自己拷。

「装完即用」这一条也真机量过：把 `dist/` 里的安装器静默装进一个空目录（`/S /D=<空目录>`），
装出来的目录里 `GyanisScribe.exe`、`ffmpeg.exe`、`tessdata/` 两份语言包、`licenses/`、
`translations/GyanisScribe_en.qm`、`platforms/qwindows.dll` 与 `Uninstaller.exe` 全在；
就在那个目录里把 PATH 收窄到只剩 `System32` 跑 `--selftest`，退出码 0，
`ffmpeg.exe -version` 也起得来（9.0.2-essentials_build）；随后 `Uninstaller.exe /S` 退出码 0，
装出来的目录和 HKLM 里那条卸载登记键都不在了。

开遮罩不装档与解锁不清档（各只打中服务那条的一格）。这一批的遮罩级用例抓到一处老 bug：
`mouseReleaseEvent` 原来直接写原始光标点，拖出的正方形在松手瞬间弹回自由形状——纯函数
一直是用例保着的，可「Move 里锁好、Release 里被覆盖」这条接线从来没人看着。

留了个教训：`CompositionMode` 只作用于「画到的像素」，直接 fillPath 圆角之外没人碰，
第一稿正是这么假绿的，被像素用例逮住后才改成整幅掩膜。

二维码识别那一批四处——preferredReading 忽略二维优先（只打中挑选口径那条）、落列表时
二维标志恒假（只打中自造 QR 往返那条）、桥不接按钮（只打中窗口链路那条，工具栏自己的

四条用例编了却没进名单，677 与 673 的差当场露出来，补上注册后名单与读数一起对上。
图标整套重绘那一批七处——App 补第二档线宽（只打中单档线宽那条）、PinTop 横线挪出安全区
（只打中安全区那条）、标注外框右移 3 格（只打中居中那条；首版移 2 格恰好落在 ±2 格容差的
边界上、判据按规格放行，换成 3 格的真突变才跑红）、RecordRegion 虚线改密（只打中家族外框
那条）、回退渲染修复与边界减半（都打亮高 DPI 的安全区、居中、满尺寸三条）、边界内缩到
(3,3,18,18)（只打中满尺寸那条）。驱动脚本第一轮六处全数「零红」：从 Python 调 cmd 写成
`//c` 不会被当开关解析，只空开一个交互 cmd 并返回 0，六轮读数全拿旧二进制跑——改成 `/c`
才见真红。这一批的判据还当场抓到一处存量缺陷：无边界 `render()` 把 viewBox 按物理像素铺满
画家视口、再叠一次缩放比，dpr=2 的图标一直是两倍大且右下半被裁（拿 HEAD 那版渲同一张 PNG
三栏对照定案，旧图标同样中招），只是从没在高 DPI 档上量过。
每批改完都复跑到全绿再进下一批；批二的字母快捷键在容器 GCC 13 下另跑过一次 ASan（本机 MSVC 绿不构成那一档的证据）。
容器覆盖率档有过一次偶发红（`PinManagerFixture.TopmostThroughAndConcealSurviveARestart`）：根因是 TestPin
的布局用例与 TestModuleFlow 读写同一份共享缓存目录（`cacheDirectory()/Pins`）却没挂同一把资源锁，
一个进程刚清掉的文件正是另一个进程要读的；`tests/Pin/CMakeLists.txt` 补上 `pinLayoutCache` 之后
这一类窗口不再存在，取证与复跑记录在那笔提交里。同一条纪律后来又拦下一类：几条借系统剪贴板
传图的用例（TestPin 的动图与直接标注、TestCapture 的选区复制、TestOcr 的结果复制、TestModuleFlow
的拖放像素回读）并行时会互相覆盖剪贴板内容，表现是「像素越界读到无效色」的假红（单跑必绿、
全量偶红，失败轮那条用例耗时 2.7 秒——Qt 在 Windows 上开剪贴板自带重试）。四处 CMakeLists
现在同拿一把 `clipboardShared`——资源锁只对「同拿一把的用例」互斥，漏掉任何一个写者或读者都拦不住。
这里还踩过一个静默坑：`gtest_discover_tests` 的 `PROPERTIES` 值里两把锁之间的分号要写成转义
（`"lockA\;lockB"`），裸分号会被 CMake 当列表分隔吃掉、只剩第一把——锁挂了个寂寞，假红又现两轮，
直到用 `ctest --show-only=json-v1` 逐条读 `RESOURCE_LOCK` 属性才现形；改完转义复核到两把、
连跑四轮全量不再复现。加锁的收尾判据从此是「当场 show-only 数一遍每把锁覆盖哪些用例」，
不只信 CMakeLists 上写的那行。
`asan` 与 `coverage` 两档的 `build_type` 就是 Debug，而 Debug 档不领 Tesseract（理由与撤除判据见 [docs/OcrBackends.md](docs/OcrBackends.md)）。
本机 Debug 那一档同样少这 4 条，另多 1 条「后端没编进来」的对照——两档条数不同是这套条件编译的结果，不是漏跑。
本机这一档跳过的四条全是要真 `ffmpeg` 的端到端（编码 2、设备枚举 1、取声 1）：这个工作树没跑
`scripts/FetchFfmpeg.ps1`，`Vendor/Ffmpeg/` 不在，所以四条一起跳——打过包的本机只跳取声那一条。
跳过的都是环境门控用例，本机两档与容器各跳哪些是清楚的：

| 跳过的用例 | 为什么跳 |
| --- | --- |
| `LanguageFixture.BuiltEnglishPackTranslatesKnownString` | 容器那份 Qt 6.4 没有 lrelease，出不了真实语言包，只能在有包的一档成立 |
| `OcrFixture.ReportsMissingBackendSeparatelyFromMissingLanguagePacks`（仅本机 Debug） | 这台机装了系统识别语言包，工厂先问 Windows 就拿到了后端，走不到「语言包在、后端没编进来」那一格；同一格由容器那两档跑 |
| `FfmpegAudioCaptureEndToEnd.*`、`VideoEncoderEndToEndFixture.*`、`FfmpegAudioDevicesEndToEndFixture.*` | 要真 `ffmpeg`；取声那一条还要一路真设备 |
| `CrashGuardEndToEnd.*` | minidump 走 Windows 的 dbghelp；Linux 侧这一格是空操作（core dump 归宿主配置） |
| `PlatformIntegration.EnumeratedWindowSitsWhereQtPutsIt` | 「屏上有哪些窗口」只有 Windows 后端给得出；能力位为假时这一格按降级出口跳过，回绝文案由同文件另一条用例钉住 |
| `ModuleFlowFixture.TrayEscapeHatchMakesThroughPinsClickableAgain` | 要真鼠标穿透能力才开得出「穿透中」的贴图，Linux 侧那一位为假；没有可复现的现场就跳过，不拿假现场充一条通过 |
| `QScreenCaptureSourceFixture.GrabbedCursorShapeIsSelfConsistent`、`...CursorDrawsIntoARealFrameWithoutBreakingItsGeometry` | 要真桌面才取得到系统指针的形状；容器与离屏档拿不到就跳过，本机在指针此刻隐藏时同样跳（这一档跳过是机器的现场，不是漏跑）。掩码与合成规则不靠这两格——`CursorPixels` 那四条用自造的位平面与自造指针跑，两边都跑得到 |

`scripts\WindowsBuild.bat` 在 `Vendor/Ffmpeg/ffmpeg.exe` 就位时会自动把它交给 `GYANISSCRIBE_FFMPEG`，
所以打过一次包的本机跑门禁时，编码与设备枚举这两条端到端是真的在跑（跳过的只剩取声那一条）。
自己指定仍然优先，本机没有随包那份时这样打开：

```bash
GYANISSCRIBE_FFMPEG=C:/path/to/ffmpeg.exe             # 编码端到端
GYANISSCRIBE_AUDIO_DEVICE=@device_cm_{...}\wave_{...} # 取声端到端（要用 dshow 的 Alternative name，不是友好名）
```

另有三条不编译源码的静态门禁，作为 ctest 用例注册在 `tests/Style/`：

| 用例 | 钉住什么 |
| --- | --- |
| `Style.QtStringPlaceholders` | `QString` 占位符不许 `{}` 与 `%1` 混用——混用编译期无声，运行时把「选择{}的目录」原样摆给用户 |
| `Style.TranslationCatalog` | 源码里每一条走 `uiText` 的文案都必须在 `.ts` 里有非空译文，否则英文档下会安静地显示中文 |
| `Style.SourceConventions` | 路径不得按窄串交给第三方库；按枚举分派的开关要覆盖每个值（MSVC 与 GCC 的默认告警都不报这种漏项） |

用例结构逐级镜像 `src/`，统一 GoogleTest，不引入第二个测试框架。
共用同一份外部资源（真实缓存目录、临时文件）的用例用 CMake 的 `RESOURCE_LOCK` 串行化——
`ctest -j` 把每条用例当独立进程启动，进程内互斥救不了。

## 已知问题

- 抓帧在 Windows 上走 DXGI 桌面重复（抓一帧中位 6.0ms，Qt 那份 `grabWindow` 同轮 30.5ms，读数见[性能实测](#性能实测)），
  它认屏按桌面坐标而不是屏名——Qt 报的是显示器友好名，与 DXGI 的设备名不是一回事。旋转过的输出、
  非 B8G8R8A8 的桌面格式（HDR 档）、远程会话与老驱动都开不了桌面重复，这些情况下按帧回落 Qt 并在日志里
  点名原因（回落时 DXGI 的取帧计数停在 0，用例钉着这一格，不让「回落也抓到了图」的假绿混过去）；
  抓窗口与取指针两格仍走 Qt——桌面重复给的是整块桌面。
- Windows 上识别首选系统组件（`Windows.Media.Ocr`），它用的是 Windows 自己装的语言包，不需要用户放文件；
  走 Tesseract 那一条也不用放——语言包由安装包带到 `<程序目录>/tessdata`，查找顺序把这一份排在用户数据目录之前。
  两样都缺时明确报「不可用」并给出放置位置，不会返回空结果冒充「这张图里没字」。
- 录屏的编码走 `ffmpeg` 子进程：随包分发那一份，**不链接**（避开 GPL 传染），所以本体源码不受它约束；
  查找顺序是「程序目录里随包那份 → PATH」。装的那份没有 `libx264` 时编码前会自己探一个开得起来的编码器顶上，
  五个候选全都开不起来才报失败。
- Debug 档不领 Tesseract：上游 leptonica 的 Debug 包库名与其 `cpp_info` 不一致，
  `conanfile.py` 里按 `build_type` 分岔并写明撤除判据。Windows 的 Debug 档仍能真识别——工厂先问系统识别。
- Linux 侧能力不全：没有全局热键后端（登记会给出中文提示并降级）、没有开机自启动（设置页那一格灰掉并写明替代做法）、
  认不出界面元素（悬停只认整扇窗口，元素那一级与 `,`/`.` 层级键一并缺席）、没有录屏取声、
  无系统托盘时菜单改由主窗口提供、`Qt::ColorScheme` 要 6.8 才有而容器是 6.4（跟随系统会解算到兜底档）。
- 界面元素检测（Windows）走「先认光标下那扇窗、再按包含关系往 UI Automation 树里钻」：UIA 自己的命中测试
  穿不过全屏置顶的遮罩（本机探针实测，工具窗也不例外），所以不是直接问「点下是哪个元素」，而是把遮罩窗
  从命中名单里排除再往下找。一次查询实测中位 0.78ms（探针窗、链深 2、20 轮，
  `PlatformIntegration.ElementChainDescendsIntoTheWindowUnderThePoint` 尾段那条读数，它不断言时间）。
  下钻有深度与子项预算两道上限（24 层 / 256 个子项）：虚拟化列表一次会暴露成千上万个条目，
  逐个取矩形都是跨进程调用，撞上限就停在当前这一层——粗一档但当场可用。
  相邻同矩形的包装层（惰性树里常见）在遮罩那一侧并成一档，`,`、`.` 按的是「块」不是「层」。
- 滚动长截图的接缝按「整段逐字节相同」认（`FrameStitch.cpp` 里按行 `memcmp`）：选区里有闪烁的光标、在放的视频
  或动图时，那两帧怎么都对不上，于是接不下去——它报「这一帧没接上」而不是悄悄接歪一张。
  要吃得下会动的内容得换成容差匹配，而那条判据先得能证伪「容差把两页开头的空白当成缝」。
- 录屏跟不上目标帧率时，成品按这一轮**实际达成**的那一档帧率铺时间轴：画面不快放，只是变卡，
  音轨也不再被截尾。达成率与墙钟对齐这件事写在[性能实测](#性能实测)那一格里，有端到端用例钉着。
- 两处路径仍按本地码页交给第三方库（各自在同一句里写明理由，`Style.SourceConventions` 认这些理由）：
  spdlog 的日志文件名（本构建没开 `SPDLOG_WCHAR_FILENAMES`，窄串要按本地码页给）与 Tesseract/Leptonica 的
  `TessBaseAPIInit3`（C 接口拿 `const char*` 开文件）。要彻底了断 spdlog 那一处，得在 Conan 侧把 wchar
  文件名选项打开，再回到 `toDisplayText` 那条路上。

  与「程序唯一的联网点是检查更新」这条自家口径冲突。

以下这些在等一个能验证它们的环境：

- **长录屏**：帧序列按 PNG 逐帧落盘，1080p 十分钟就是 GB 级（实测屏幕内容一帧约 210KB，15 帧率十分钟约 1.9GB）；
  换成喂 ffmpeg `rawvideo` 管道才能放开时长上限。
- **录屏逐帧写 PNG 仍在界面线程上**：需求的硬约束要求「耗时操作放工作线程」，现在只剩这一处
  （`PngSequenceSink::write`：一帧的写盘时间直接算进下一格的等待）。
  文字识别与停止后的编码都已交出去：`Ocr::RecognitionRunner` 与 `RecordingService::startEncoding`
  都走 Qt 的全局线程池，认完/编完由 `QFutureWatcher` / `QFuture::then`（context 是界面线程那个对象）送回界面，
  两处都同一时间只跑一条，析构前等手上的任务跑完。
  **恢复条件**：这一处要与采集循环交接帧与状态，并发改动要有 TSan 才算判据（本机 MSVC 没有 TSan，
  而容器里 `setarch -R` 被 Docker 默认 seccomp 拒绝），先用 `--security-opt seccomp=unconfined` 起一档、
  证明旧写法报得出竞态，再动它。没有这一档之前把跨线程手抖写进去，只是把可复现的卡顿换成不可复现的竞态。
- **Linux 录屏取声**：Windows 那一路已经落地，Linux 的入口是 ALSA/Pulse，容器与本机的验证环境都没有
  可登记的音频设备，写进去就是一段没人验过的代码。现在那一侧列出设备与取声都直接给出中文降级原因。
- **Linux 全局热键**：`Platform` 抽象下只有 Windows 后端有真登记，Linux 侧给出中文降级提示；
  要做得接 X11/Wayland 各自的快捷键协议。
- **界面截图与演示**：本文档暂时没有截图，等打包产物稳定后补真实界面图，不放占位图。
- **录屏最长时长是个常量**：默认 600 秒、硬上限 7200 秒，到点自动收尾，界面上既没有这一格也不说这句——
  录满十分钟自己停下来，用户只能猜。要么给它一个设置项并把「到点就收」写进控制条的提示，要么放开上限交给磁盘。
- **GIF 的帧率天花板与设置页不同解**：`RecorderConfig` 判 GIF 只能到 24 帧，设置页那一格却允许填到 60，
  差别要到开录那一刻才拒。修法是按当前输出格式算那一格的取值范围，而不是让用户撞一次拒绝。
- **指定屏幕截图还没有入口**：`captureFullScreen(screenName)` 这条通道与它内部按名字找屏的逻辑都在
  （跨模块用例就在点名一块屏），但托盘与主窗口只放「整屏截图」一条，走的是光标所在那一块。
  多屏上想点名另一块屏，得先给这一条加上一份屏幕清单的入口。
- **`AppController` 那一层没有直测**：构造函数自己造出设置、抓帧、托盘、编码这些真模块，没有注入口，测试里一个实例都没有。
  延时截图的路由与成品进历史那几条都住在这一层，本轮「截取当前窗口绕过延时」就是这么漏下来的——只能靠人读代码发现。
  前置工作是给它一套与 `tests/App/TestModuleFlow.cpp` 同形状的替身。
- **图标接线**：需求第七节点名要有的那批 SVG 里，还有 8 枚在界面上一次都不出现（`Microphone`、`SystemAudio`、
  `Countdown`、`OcrLanguage`、`OcrRegion`、`ThemeLight`、`ThemeDark`、`ThemeSystem`）。它们由
  `tests/Ui/TestIconProvider.cpp` 那份独立清单逐张核对画得出来，所以不是坏资产，只是还没找到配得上的落点：
  两路取声是整条下拉共用一个图标（一排里同一枚挂着没有区分作用）、主题那三档缺高对比度对应的第四枚
  （只给它三枚会看着像漏了）、倒计时与语言包各自只有一处文字读数、`OcrRegion` 与托盘那两种识别入口的语义对不上。
  其余几枚（三档录制范围、五种截图去向、托盘的「截取当前窗口」、录屏页的光标高亮那一行）已经接上。
  贴图右键菜单与录屏页两处取声没有接：前者要为此把图标供给器一路穿过 `PinManager` 的构造链，
  后者是整条下拉共用一个图标，为观感拉一条链子不划算。
- **自动更新只做到「查」**：下载、校验与替换可执行体要先有代码签名与原子替换那套方案——
  替换到一半失败会把用户的程序留在半坏状态，而这不是截图工具该自己发明的机制。在那之前，
  关于页把新版号与发布页摆出来，下载与覆盖安装交给用户自己。
- **剪贴板里的链接与文件还不能转贴图**：图像、纯文本与颜色三种已经能贴（文本渲染成卡片、
  颜色渲染成色卡）。链接按纯文本贴会丢掉「点得开」这个意思，文件路径与文件列表要的是另一套
  「复制文件本身」的语义，两条都要先想清落到屏幕上该是什么东西，想清之前不做。
## 参与贡献

改动要么修掉错误行为，要么加上需求里的能力。上手顺序：

1. 按[从源码构建](#从源码构建)跑一次本机的构建脚本——它一条命令包含配置、编译与 `ctest`，绿了才谈改动。
2. 写完先跑 clang-format（仓库根的 `.clang-format`，`ColumnLimit: 180`），只递给源文件，别把 `CMakeLists.txt` 喂进去。
3. 再跑对应平台的门禁：本机 `scripts\WindowsBuild.bat <preset>`；改到并发、生命周期或跨线程代码时，
   容器两档也要跑（`sanitize.sh`、`coverage.sh`）。**本机全绿不构成并发正确性的证据**——MSVC 没有 TSan。
4. 加功能要带用例，`tests/` 的目录结构逐级镜像 `src/`；每条用例说明它钉住什么，并且能红：
   把实现改回缺陷行为确认这一条会失败，再提交。
5. 提交信息用中文写「为什么」而不是「做了什么」，一次提交只讲一件事，
   格式是约定式提交 `<类型>[(范围)]: <描述>`（类型取 `feat` / `fix` / `refactor` / `perf` / `test` / `docs` / `build` / `chore`）。

规范要点（细节见 [docs/ProjectRequirements.md](docs/ProjectRequirements.md) 与 `tests/Style/` 三条门禁）：

- 文件与类名 PascalCase、接口 `I` 前缀、函数 camelCase、成员 `m_` 前缀、常量 `k` 前缀，标识符不用缩写。
- 声明处中文 Doxygen（重写的方法要独立写全），实现体在分支、状态流转、加锁、魔法数字处写中文 `//`；
  注释只留「为什么」，不写实现历史与「旧实现怎样、现在怎样」。
- 可恢复错误返回 `std::expected<T, Error>`，错误文案中文且可操作（写清「原因 + 替代做法」）；
  不许静默失败、取整、回绕、把「不支持」悄悄当成「按默认处理」。
- 一切要显示给用户的文本走 `Core::uiText()`，并且同步进翻译目录（`Style.TranslationCatalog` 会拦漏项）。
- 图标必须是原创 SVG：`viewBox="0 0 24 24"`、`currentColor`、描边 1.5 或 2、圆角端点，
  只经 `IconProvider` 加载；不下载、不引用、不复制任何现成图标库或任何现有产品的素材。
- 零告警是硬判据：MSVC 侧每个目标都带 `/W4 /WX`；容器侧的 GCC 预设没开 `-Wall`，
  这类编译器不报的漏项由 `Style.SourceConventions` 与用例兜住。
