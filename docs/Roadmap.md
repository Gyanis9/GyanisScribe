后续与残留：

- ~~短片段导出（1b，可选）~~ **已做（2026-11-12）**：选择器里 `[` / `]` 标起终点、底部「导出片段…」导成 MP4；
  编码复用录屏那条「帧目录 → 视频」管线，无音轨、不进历史。片段最长就是缓冲时长（默认 10 秒）。
- **30 分钟长跑与 4K 门禁未做**：已测 1440p / 10 秒档 / 60 秒采样的 p50 / p95 / p99，
  但没有 30 分钟连续采样，也没有 4K 桌面的抓帧与内存读数；ADR-001 的长跑门禁仍待在能静止的机器上补。
- **首帧冷启动离群**：开桌面重复、建暂存纹理与首帧全黑回落只发生一次，第一次抓帧可能是数十毫秒；门禁读数预热后丢弃这一帧。
- **真黑屏回落**：Qt 回落帧本身全黑时没有非黑帧可缓存，0 超时路径会每格走一次阻塞回落；这是「交付最近一次真实画面」的残余代价。
- **托盘读数只到信号层**：`TrayController` 的回溯状态字段仍是私有的，用例只覆盖 `bufferStatusChanged`；缺一个「托盘到底存了什么」的只读访问器。
- **导入配置绕过隐私确认**：通用页「导入配置…」可以把 `Rewind/Enabled` 直接导成 true，不重弹开启确认。
- **崩溃转储已复核**：转储档位只写线程栈与异常现场，不取间接引用的堆页；内存里的回溯画面不会随 `.dmp` 落盘。
  栈上仍可能残留与画面相关的指针或短片段（例如调用参数），但不会构成整帧画面。
- **普通截图/标注仍被采样**：回溯只在自己起的流程（选择器、回溯框选、其后的标注）里暂停；普通截图与普通标注不会暂停缓冲，
  热键虽被拦下不叠窗，遮罩与标注窗仍可能进入胶片条（spec 4.2 的自家窗口自采样缺口）。
- **一次性命令行启动也起缓冲**：开启回溯时，`--capture` 这类一次性进程在存活期间会抓帧（只存内存），未按命令行装配区分。
- **隐私确认文案固定 10 秒**：对话框正文按 spec 4.1 写死「最近 10 秒」，保留时长改成 5 或 30 秒后不跟着变。

## 智能隐私打码（Phase 2，已实现）

**2026-11 已落地**：标注窗工具栏的「隐私打码」在本机做一次文字识别与二维码检测，列出可逐项取消的审核清单，
确认后按马赛克（默认）或高斯模糊批量落笔，整批只占一步撤销。手机号、固定电话、身份证（GB 11643 校验位）、
银行卡（Luhn）、邮箱、IPv4（IPv6 只做基本格式）与二维码/条形码都在本轮范围内；全程不联网、不上传、不落盘，
识别文本只在内存里参与匹配，不写日志与历史。用户向的行为与限制见[使用指南 · 隐私打码](UserGuide.md#隐私打码)。

后续与残留：

- **姓名、地址、头像/人脸、聊天头部不在 Phase 2**：这些要么依赖命名实体模型，要么依赖人脸/版面检测，
  与本轮「纯规则 + 现有 OCR/条形码后端」不是同一条技术路线，留给后续立项。
- ~~批量长截图打码未做~~ **已做（2026-11-12）**：长截图落地标注窗后自动发起一次隐私打码；识别后端对超高的图会整张拒绝，所以先按 1200/120 物理像素分带扫描再合并，审核窗与可撤销落笔沿用原链路。
- **一维条形码的定位框可能只覆盖解码行**：zxing 给的一维定位框可能只是一条窄带，打码框以它为中心撑到至少 32 逻辑像素高
  （原框更高时再补 8）；常见的小条码能被盖住，但特别高的条码仍可能露出上下边，框与本体高度的贴合度没有逐张实测。
- **审核窗没有图像预览**：清单只给「类型：脱敏样例」，命中框长什么样要等落笔后在画布上看，不满意按一次 `Ctrl+Z` 全退。
- **已知漏检与误报**：全字母 IPv6（如 `face:beef:cafe:dead:babe:feed:face:beef`）不识别；前面隔一个空格的
  `Version 1.2.3.4` 这类四段数字都合法的版本号会被当成 IP；`861[3-9]` 开头的 13 位真实银行卡会被认成手机号
  （仍会打码，只是类型标签写成手机号）。此外，成排短数字用空格或短横线连在一起时，某个 13–19 位组合可能
  碰巧通过 Luhn 而被列成银行卡；互相重叠的候选会合并成一整段，宁可多盖也不漏盖，审核时取消勾选即可。
  这几条是有意取舍：要求候选里至少一位数字、86 区号优先于银行卡形状，以及按分组边界重试卡号子段。
- **检测不承诺安全**：校验位与 Luhn 只降噪，OCR 漏字、多词中文、旋转与低分辨率都会带来漏报/误报；文案固定提醒用户自行检查。
- **OCR 词框质量**：命中优先取词框并集，词框切边或不可用时回退整行框，整行框会比实际内容宽一圈。
- **二维码扫描在 OCR 之后同步跑**：现有后端是同步调用；若后续实测单张超过 50ms，需要移到工作线程。
- **命中路径的落笔坐标只有组件级判据**：检测器、引擎与对话框各有用例，`CaptureCoordinator` 的物理框到逻辑框换算由
  `Core::Privacy::logicalRedactionRect` 的单测钉住；审核窗是模态的，没有端到端断言最终落笔矩形。
- **贴图上的直接标注不提供入口**：没有审核宿主，工具栏那一枚在贴图窗里收起（与既有扫码按钮无宿主同一种现状）。
- **等待期间画布变化会被丢弃**：用 `cacheKey` 挡住刷新/重裁后的旧结果，用户需重新点一次；这是有意的取舍，不是漏检。

## 截图记忆（Phase 3，已实现）

**2026-11 已落地**：截图记忆默认关闭，第一次产生可索引截图时弹一次授权；只索引用户主动截的图（进入历史的截图成品），
在本机 SQLite/FTS5 里建 OCR 全文、应用、标题、时间与尺寸索引；记忆库页支持关键词、应用与时间筛选、单页 200 条上限提示、
dHash 近似重复合并与旧图文件夹导入。OCR 文本、窗口标题与进程名只写本地数据库，不上传、不写日志；排除应用、从记忆库移除、
清空索引三条路径都可用；10,000 条上限与单条 64 KiB OCR 文本上限让成本可见。用户向行为与已知限制见
[使用指南 · 截图记忆](UserGuide.md#截图记忆)。

性能读数（本机 Release，单屏 2560×1440）：

- 10,000 条索引、5 个中文关键词（报价、合同、项目、报告、截图）各查 4 次共 20 次，平均 **16 ms**；
  Debug 同一用例平均 45 ms。
- 500 张合成图导入 + 后台 OCR 收口 + 三页关键词检索合计 **8,115 ms**（单独重跑；Release 门禁里同一用例 8.63s，
  Debug 门禁 9.67s）。
- 产品目标与用例护栏分开看：1 万条查询的目标是 Release ≤200 ms、Debug ≤2 s，`TestCoreMemory` 按这两档断言；
  500 张导入与检索的目标是 ≤10 s，`TestAppMemoryCoordinator` 只断言 <60 s，11–59 s 的回归会通过用例。
- 容量读数：条目上限 10,000；单条 OCR 文本按 UTF-8 上限 65,536 字节；页脚报数据库主文件与 `-wal` 合计字节。

后续与不做：

- **语义/向量搜索、图片内容理解、人脸与物体识别不在 Phase 3**：本轮是字面 FTS5 加元数据筛选，不做嵌入与模型推理；
  要做需另立计划，并先解决本地模型体积与隐私边界。
- **手动标签 v1 不做**：迁移路径预留给 `tags` / `item_tags`，v1 不建空表；等真实需求出现再加。
- **录屏与回溯帧不索引**：只索引用户主动交付的截图成品；把回溯缓冲或录屏帧写进索引与「不做全时记录」的承诺冲突。
- **导入条目依赖原路径**：导入不复制文件，原图移动、改名、删除或外接盘未挂载后，下次进记忆库页会清掉索引行；
  要长期留存请把文件放在稳定路径。
- **数据库不额外加密**：只依赖 Windows 用户配置目录的权限；需要更强保护时由用户自行启用系统磁盘加密。
- **dHash 阈值 4 的误合并**：相似版式可能并成一组；「合并重复图」可关，分组只作用于当前结果页、不改数据库。
- **OCR 质量决定命中率**：旋转、低分辨率与艺术字会漏搜；文件名、应用、标题与时间可兜底。
- **容量淘汰只动索引**：到 10,000 条后先淘汰最旧的导入条目、再淘汰最旧的截图条目，原图不动。
- **未实测**：十万级以上的真实库、多个 Windows 账户共用同一配置目录、非 Windows 平台的 `QSQLITE` 与 FTS5 可用性。

## 识别结果内容动作（Phase 4，已实现）

**2026-11 已落地**：文字识别的结果窗口新增一排内容动作，按这一份结果里有什么决定露出哪一枚。
认出文字即可「复制 Markdown」，把这一份结果按版面启发式转成标题、列表、代码块、段落与表格放进剪贴板；
检测到简单表格时多一枚「导出表格 CSV」，按 RFC 4180 最小引用写出 CRLF 行尾并带 UTF-8 BOM，Excel 可直接打开。
表格检测只读 OCR 词框的对齐关系，不依赖表格线；复杂表格（合并单元格、多级表头、文字跨列、行内缺格）只提示不导出。
内容动作只处理用户主动发起识别后的这一份结果，不自动 OCR、不开后台扫描、不联网。用户向说明见
[使用指南 · 文字识别](UserGuide.md#文字识别)。

后续与残留：

- **一次只认一张表**：有多个候选时简单表优先，同类取行列乘积最大的一张；其余表格不会出现在 CSV 里。
- **复杂表不导出**：合并单元格、多级表头、文字跨列、行内缺格或各行格数不一致都会判为复杂表，CSV 按钮隐藏；
  Markdown 与 TXT 仍取得到文字，但拿不到按列还原的表格结构。
- **没有字体信息**：OCR 结果只有文字与词框，不加粗、斜体、字号变化都无法还原，标题只按行高推断。
- **代码块只围栏平铺缩进**：连续至少两行带缩进、含代码符号或基本全 ASCII、且不以中文句末标点结尾才包成围栏代码块；
  相邻行缩进差超过 0.5 个字符宽就断开，词框之间的内部缩进不重建，复制后需要自行补排版。行首符号与缩进决定列表，
  版式相近的正文可能被误判，此时改用纯文本复制或导出 TXT。
- **表格检测的误判边界**：只读词框对齐；同一格里的词距过宽会被拆成两格，紧贴表格上方的单行短标题可能被并进候选段
  而判成复杂表或稀疏表，复杂版式仍可能误判，导出前应人工核对。
- ~~CSV 公式注入未做净化~~ **已做（2026-11-12）**：单元格跳过前导半角空格后，以 `=`、`+`、`@`、制表符或回车开头的一律加
  `'` 前缀；以 `-` 开头的只有「不是负数」才加，`-5`、`-3.2`、`-1e5` 保持原样。前缀在 RFC 4180 引用之前加，
  Excel 之外的消费端会看到这个前导单引号。
- ~~XLSX 未做~~ **已做（2026-11-12）**：与 CSV 并排的「导出表格 XLSX」，单工作表、`inlineStr`、无样式/无公式/无合并，
  不引入第三方依赖（store-only ZIP 自写）。需要多工作表、单元格格式或公式时仍得另立计划。
- **真实样本验收待人工**：50 张真实表格的简单表 CSV 准确率 ≥90% 与 20 篇 Markdown 样本的阅读顺序仍是人工项，
  合成用例只钉住规则与边界，不证明真实版面。
  2026-11-12 已由 agent 用 50 张自建渲染表格与 20 篇 Markdown 执行：端到端 CSV 准确率 0/50——WinRT OCR 按「每格一行」输出而检测器要求整行成句；
  2026-11-13 已修（检测前把同一视觉行的多格行并成逻辑行，分段上限兼顾单元格内边距，缺一格的长留白不再串联列分界）。
  重跑按三层口径记录：simple/wide/mixed 三类 37/37 的行列结构与真值一致；按同一份 OCR 词框算的 OCR 可达逐格精度 32/37；
  按真值文字算的原始逐格精确 0/50、mean-cell 18.8%——受 OCR 文本保真限制，逐格精确不是检测器判据。
  20 页原语料无误判；两栏正文守卫加入后按正常行距语料复核无表格误判（正常行距的两栏正文由新守卫判为复杂表，见单测）。
  剩余误差来自 OCR 文本本身（「值」被读成「亻 直」、相邻表头被并成一行）与整行空白的稀疏表——OCR 里没有信号，逐格精确无法还原；
  真实版面多样性仍是残余风险。

## 聊天长截图增强（Phase 5C，已实现）

**2026-11 已落地**：滚动长截图的接缝判定从「整段逐字节相同」换成容差匹配——单个像素任一颜色通道差不超过 8、
一行里至多约 1% 的像素不同、整段至多约 2% 的行不同都仍算接上；容差搜索落空时再按逐字节相等找一遍
（旧判定的兜底；默认宽容度下容差已覆盖逐字节相等），纯静态页面照旧能接上。零星的动效（闪烁的光标、贴边的一两条细窄动画）因此不再让整帧失败，
成片的动图或视频超过这两档比例时仍判失败。
聊天窗与网页的固定标题栏、底部输入框被认成粘性头尾：首帧顶部与底部各取四分之一帧高作为参考带，后续帧的首尾
与它连续对上至少 8 行时跳过它们，标题栏只在成品顶部出现一次，输入框不进成品；第一次认出来时把已经写进缓冲的
那一段吸底尾一并裁掉。粘性头尾只在整帧对不上（重叠少于 24 行）时第一次尝试；认出来之后每帧先核对参考带
是否还在，在就继续跳过，不再要求整帧对不上。
真没有可信重叠时 `FrameStitcher::append()` 返回 `InvalidArgument`，长截图当场停下并提示「回到上一段末尾附近、
等画面停稳后再滚一小段；已经滚过一屏就缩小滚动幅度重来」——不再把整帧硬接出一张重复的长图。
用户向说明见[使用指南 · 截图](UserGuide.md#截图)。

后续与残留：

- **动图超过容差仍失败**：变化面积超过约 1% 像素/行或 2% 行就判为没有可信接缝，这一轮停下并要求重来；不做局部跳过、模糊或光流对齐。
- **粘性带高度变化不重新裁**：参考带只取首帧的顶、底四分之一帧高，且连续对上的不足 8 行不算粘性；之后只核对原参考带是否还在——标题栏收起会让顶部对不上而停止跳过，输入框变高是往上长、底边仍对得上，多出的行会当内容接进长图，可能多出一条输入框或让下一帧接不上。
- **底边整条参考带都对上时不裁尾**：输入框连同上方一小段内容恰好都没变（画面几乎没动时常见），分不清哪几行是输入框；这一帧不裁尾，没有新内容就原样通过，有新内容则按无接缝停下——宁可多留一次输入框，也不静默裁掉内容。
- **只有整帧接不上才首次启用粘性判定**：还没认出头尾时整帧能对上就照常把头尾随中间帧留在长图里，不会为了「更干净」而主动裁；认出来之后改为每帧先核对参考带。
- **已裁掉的输入框不回补**：吸底尾只在第一次认出时从缓冲末尾裁一次，之后即使输入框消失也不会把裁掉的行补回来。
- **矮帧整帧追加**：高不足 24 行的帧不参与接缝判定、整帧接上；一次滚过一屏（重叠不足 24 行）则失败而不是重复。
- **往回找重叠最多 1200 行**：重叠超过这个数按没有重叠处理。
- **粘性参考带只覆盖四分之一帧高**：比这更高的固定栏认不全（把任务栏整条框进选区就是这种），会照旧每帧接进长图。
- ~~不自动打码~~ **已做（2026-11-12）**：拼接后的长图落地时自动走一遍隐私扫描（分带）并弹审核窗，命中项默认全选、落笔是可撤销的图形；扫描失败的带会让整次退回，不会交半截结果。
- **真实样本验收已由 agent 执行（2026-11-12）**：50 个自建长页（Edge 渲染、真实粘性头尾）接缝成功率 46/50 = 92%，4 页因重复内容少 2–21 行；真实窗口滚动抽查未跑通（脚本化注入未生效）。真实站点（动态加载、滚动惯性）仍是残余风险。

## 一键清场截图（5B，已实现）

**2026-11 已落地**：一次交互式截图：托盘「清场截图」、默认热键 `Ctrl+Alt+X`、主窗口动作条与快捷键页四路都能起；
平台能力位给不出清场的机器上，这几处入口一并收起。清场范围是隐藏桌面图标（`SHELLDLL_DefView` → `SysListView32`）
并借系统的「最小化全部」让其他窗口让开，之后照常铺遮罩框选，截完用「撤销最小化全部」把它们还原。通知不做——要安静通知得改专注助手，
侵入性高，宁可让用户自己关。光标沿用遮罩已有的「含指针 / 不含指针」档（裸按 `P` 翻这一轮），清场入口默认不含。

后续与残留：

- **窗口的让开与还原是一对明确命令**（shell 的「最小化全部 / 撤销最小化全部」），不是切换状态：清场期间若自己按 `Win+D` 提前把窗口收回来，恢复那一步对已还原的窗口无副作用；恢复失败时按一次 `Win+D` 即可取回。
- **崩溃兜底依赖下次启动**：清场标记只在下次启动时补恢复（放回图标并撤销那一次最小化全部）；若清场后直接杀掉进程且不再启动本程序，图标仍隐藏——可在桌面右键 → 查看里重新勾选「显示桌面图标」，窗口按 `Win+D` 取回。
- **恢复会放回桌面图标**：若你本来就关着桌面图标，恢复后会显示出来，可在桌面右键 → 查看里再关掉。
- **只服务一次交互式截图**：不提供清场下的滚动长截图或录屏；这两条路自己管屏幕，与清场的恢复时机对不上。

## 已知问题


- 抓帧在 Windows 上走 DXGI 桌面重复（抓一帧中位 7.3ms，Qt 那份 `grabWindow` 同轮 28.8ms，读数见[性能实测](Development.md#性能实测)），
  它认屏按桌面坐标而不是屏名——Qt 报的是显示器友好名，与 DXGI 的设备名不是一回事。旋转过的输出、
  非 B8G8R8A8 的桌面格式（HDR 档）、远程会话与老驱动都开不了桌面重复，这些情况下按帧回落 Qt 并在日志里
  点名原因（回落时 DXGI 的取帧计数停在 0，用例钉着这一格，不让「回落也抓到了图」的假绿混过去）；
  抓窗口与取指针两格仍走 Qt——桌面重复给的是整块桌面。
- Windows 上识别首选系统组件（`Windows.Media.Ocr`），它用的是 Windows 自己装的语言包，不需要用户放文件；
  走 Tesseract 那一条也不用放——语言包由安装包带到 `<程序目录>/tessdata`，查找顺序把这一份排在用户数据目录之前。
  两样都缺时明确报「不可用」并给出放置位置，不会返回空结果冒充「这张图里没字」。
- 录屏的编码走 `ffmpeg` 子进程：随包分发那一份，**不链接**（避开 GPL 传染），所以本体源码不受它约束；
  查找顺序是「程序目录里随包那份 → PATH」。装的那份没有 `libx264` 时编码前会自己探一个开得起来的编码器顶上，
  五个候选全都开不起来才报失败。
- Debug 档不领 Tesseract：上游 leptonica 的 Debug 包库名与其 `cpp_info` 不一致，
  `conanfile.py` 里按 `build_type` 分岔并写明撤除判据。Windows 的 Debug 档仍能真识别——工厂先问系统识别。
- 界面元素检测（Windows）走「先认光标下那扇窗、再按包含关系往 UI Automation 树里钻」：UIA 自己的命中测试
  穿不过全屏置顶的遮罩（本机探针实测，工具窗也不例外），所以不是直接问「点下是哪个元素」，而是把遮罩窗
  从命中名单里排除再往下找。一次查询实测中位 0.78ms（探针窗、链深 2、20 轮，
  `PlatformIntegration.ElementChainDescendsIntoTheWindowUnderThePoint` 尾段那条读数，它不断言时间）。
  下钻有深度与子项预算两道上限（24 层 / 256 个子项）：虚拟化列表一次会暴露成千上万个条目，
  逐个取矩形都是跨进程调用，撞上限就停在当前这一层——粗一档但当场可用。
  相邻同矩形的包装层（惰性树里常见）在遮罩那一侧并成一档，`,`、`.` 按的是「块」不是「层」。
- 滚动长截图的接缝按容差认（`FrameStitch.cpp`）：单像素通道差不超过 8、一行里约 1% 的像素不同、整段约 2% 的行不同仍算接上；
  动的那块更大时判为没有可信接缝，这一轮停下并提示重来，而不是接出一张重复的长图。粘性头尾只按首帧顶、底
  四分之一帧高的参考带比对，比这更高的固定栏认不全，会照旧留在长图里（用户向口径见[使用指南 · 截图](UserGuide.md#截图)）。
- 录屏跟不上目标帧率时，成品按这一轮**实际达成**的那一档帧率铺时间轴：画面不快放，只是变卡，
  音轨也不再被截尾。达成率与墙钟对齐这件事写在[性能实测](Development.md#性能实测)那一格里，有端到端用例钉着。
- 两处路径仍按本地码页交给第三方库（各自在同一句里写明理由，`Style.SourceConventions` 认这些理由）：
  spdlog 的日志文件名（本构建没开 `SPDLOG_WCHAR_FILENAMES`，窄串要按本地码页给）与 Tesseract/Leptonica 的
  `TessBaseAPIInit3`（C 接口拿 `const char*` 开文件）。要彻底了断 spdlog 那一处，得在 Conan 侧把 wchar
  文件名选项打开，再回到 `toDisplayText` 那条路上。
